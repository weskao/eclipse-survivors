## Evidence and release gates

For each Stage, root TODO contains task checkboxes and separate release gates. Use standard `- [ ]` / `- [x]`. A verified task updates its matching detailed Wave step(s), not the whole Wave prematurely; master and roadmap link to root TODO for status. Record exact SHA, RED failure, GREEN, refactor, test commands, CI URL, manual/device/audio/art gates and unresolved blockers in `docs/es5/evidence/stage-NN/verification.md`. No invented evidence, no committing RED-only tests, no weakening existing tests. Each numeric change records JSON path, key, before/after, unit, delta/% (N/A new or zero base), reason, task ID, approval and measured paired result in `balance-report.md` and machine-readable `balance-changes.json`; baseline/candidate CSV or JSON, flags, seeds, policy, version, legal builds and mode/difficulty; use same conditions. Report variance/sample counts and censored endless runs; bot outcomes not human win rates. If no numeric change record an explicit no-change result. Reports are evidence, not a second runtime balance source.

Release-ready requires applicable actual QA and exact-HEAD tests/CI, including `make verify`, applicable scoped rules and real player paths. Follow [release process](../release-process.md) for locked dependencies, bilingual CHANGELOG and package version matching, next published patch step (99 carries), authorized --no-ff integration into develop, separate main approval, actual Pages deployment, tag/Release and desktop/mobile smoke. Version bump is coordinated with the actual release, never guessed or preallocated to unfinished stages. Mark merged, published and production verified separately only when evidenced. ES3-only manual waiver does not carry to ES5. No automatic actions/merge/deploy.
