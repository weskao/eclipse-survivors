# ES4 Hall visual and interaction implementation contract

Use the existing Eclipse Survivors dark fantasy art direction. Contemporary game conventions: compact node constellations and focused detail panels rather than dashboard card grids; restrained dark surfaces, engraved metal, meaningful palette by discipline, and legible hierarchy. References are layout inspirations, not copied visual assets.

- Preserve original core research and shared HallGrowthBoard. Add a discrete constellation entry; six medallion-shaped discipline/hero controls, distinct signature geometry, selected-state underline/rim and one action. Avoid repeated oversized rectangular buttons and gratuitous neon glow.
- Mobile: 44px hit targets, safe-area inspector, no forced scrolling; short landscape side panel; fine pointer hover preview; keyboard arrows, focus and Escape. Maintain selected category and per-tree node selection.
- Progress: actual rank, requirements, cost, owned vs equipped; no spend on preview. Until authoritative storage and gameplay are ready, show an explicit preview state with disabled transaction. Never simulate success or deduct currency for placeholders.
- Art: 72 semantic temporary SVG icons, each with a stable future 3× transparent WebP path and a visual brief. Future asset replaces SVG through reviewed manifest; no SVG is production art approval. Existing hero identity and art preserved. Use one consistent pictogram family and silhouette, not 72 unrelated fantasy stickers.
- Motion: finite entry transition, restrained hover, inherited rank progress/Shimmer and transaction-gated celebrations; full motion/flashing alternatives, no endless decorative loops. Each rank and route sound must use existing audio bus. Signature and resonance-specific art/audio remain gated on real unlocks.
- All designs must pass bilingual viewport, text wrap, keyboard, touch and actual audiovisual review. No claimed approval before evidence.

## Completion and provisional asset gate

- The current catalog and manifest contain 72 temporary SVG icons with 72 distinct final WebP paths. The five legacy nodes reuse existing art. Rank changes, locking, selection, attunement, progress rings and Shimmer are shared UI treatments, not separate raster assets.
- The owner explicitly accepts the existing semantic SVG format for functional ES4 delivery; the 72 final WebP replacements are non-blocking visual optimization. This is a narrowly scoped provisional-art exception, not a replacement for the repository WebP and asset admission rules. Retain each icon's stable path and individual art brief in the catalog and manifest; update both if genuinely new assets are required (including battle VFX, if applicable). Do not use temporary status to bypass final review or imply production art is accepted.
- Allow real talent purchases only when the corresponding effect, transaction, persistence and run snapshot are authoritative and tested. SVG-backed functional implementation and actual UI/audio/device acceptance remain required; final Hall raster replacement is a separate, non-blocking optimization. Never keep an apparently purchasable placeholder or mark the final art checklist complete without reviewing real WebP assets.
- Use the ES4 roadmap and TODO as the work queue. Follow repository TDD: reproduce a failing test locally, implement, rerun, refactor; commit green slices rather than intentionally broken test-only commits. When a check cannot be run, leave its acceptance item unchecked and record the precise limitation. Continue other independent work instead of treating a queued CI as the only remaining action.

## Completed-node visual hierarchy
- Derive completed state from authoritative rank and cap, never a missing price or read-only state. Multi-rank maxed nodes retain a gold MAX plate, full ring, engraved side facets and crown jewel even when not selected or after reload; one-rank unlocks retain a distinct restrained seal and 1/1 (ownership is not attunement). Never recolor or replace the original icon. All share one medallion footprint and one inspector.
- Only the confirmed final purchase animates the permanent crest's finite forging/inscription sequence alongside existing milestone audio and particles. No continuous idle pulse, no fake replay on reload, no geometry or hit-area changes. Reduced-motion/flashing settings keep the permanent visual state while suppressing the animation. Verify both locales, real viewport geometry and final upgrade transitions.
