## Development / verification

From repo root:

    pnpm install --frozen-lockfile
    npm ci --prefix experiments/pixijs-knight
    pnpm dev

Open the actual game at http://localhost:5173/?knightPixi=1 and choose Knight. Without the query or dependency, the original renderer remains active. Inspect the main canvas data-knight-renderer attribute: loading / pixi / canvas (actual successful draw). Use ?knightPixi=0 for identical baseline. The isolated preview is still available separately. No generated artwork was added. Do not treat a front-facing mesh as an eight-direction master.

Original source is src/assets/knight.webp (Git blob c0d956cf7d7d02d51879b61aa0986deec7559792), native 340×345 with alpha. At 108×134 game pixels it is below the required 324×402 minimum height; the 3x framebuffer does not manufacture native detail. No upscaling or false native3x claim. Directional admission: E, SE, S, SW, W, NW, N, NE need actual approved views/layers (or documented safe reuse); no shield is visible on the existing Knight master, do not invent one without a design decision. Require native 3x actual detail, clean transparent WebP via Polytool, canonical identity, stable foot/grip anchors, original sword silhouette, independently correct handedness, verified occluded areas, source hashes and QA_PENDING until visually accepted. Do not remove existing art.

A small 3x actor framebuffer, persistent textures, precomputed joint weights and one engine-owned draw are bounded. GPU-to-Canvas compositing can be costly, and is specifically experimental; profile CPU/GPU/memory/thermals against the existing single Canvas renderer before deciding on a production single-renderer migration. The root lockfile is deliberately unchanged to keep the experimental package isolated. The isolated package-lock.json was generated by a successful CI npm install and committed with the original Git blob hash. Future CI uses npm ci. Never merge this branch as production-ready without the full gates in CLAUDE.md.
