## 處理決策與缺口

1. **保留已入庫來源，不批次重繪。** 目前抽查無須另造同名資產；缺失是原生三倍來源不足、疑似斷片、部分重複動作、真正遊戲實測／人工簽核不完整。
2. 若要排除這些 blocker：先確認原始母圖是否保有真實細節，再對不合格格畫或整張幀做**真正重製**。不能單純放大 96px WebP；必須先提交真實文件／素材，再由整合者同步 Canvas source rect 與 manifest / tests。
3. 任何 image update 須先新增 RED 回歸測試、驗證失敗，然後最小修正成 GREEN；核對 hash、Alpha、是否借用隔壁格、正確展示與 CI。
4. 外部英雄作業獨立；本分工不能修改 `src/assets/es2/production/heroes/**`。
5. 繼續保留 blocking QA gate，未獲授權人工確認不得把 `visual-review-required` 換成 approved。
6. 此文檔為 source-only 審查證據；**不可**誤寫成實際戰鬥 10 種敵人／4 魔王／全部場景或全部 UI 已通過瀏覽器驗收。

## 第二階段：實際 GitHub Actions WebP 像素分析證據

- 資料來源：GitHub Actions [45170008905](https://github.com/weskao/eclipse-survivors/actions/runs/45170008905) 的 \`es2-world-art-source-review\` artifact（2026-11-23）；包含 20 項原始 WebP、當時的 manifest 與源圖 \`assets/images/imgs5.png\`、\`imgs6.png\`。
- 直接解碼 20/20 WebP、逐檔核對 SHA-256：**20/20 全部相符**；10 個 body 是 \`576×96\`／6 格，10 個 telegraph 是 \`96×96\`／1 格。
- 實際檢查 **70 格**（60 個 body 格 + 10 個警示格）。在 alpha >2 門檻下，邊界觸碰像素 0；檢查 50 組相鄰 body 格的完整 RGBA 像素，**無完全相同的相鄰影格**。注意：「沒有完全相同」不代表 6 格姿勢有效、連續或沒有原始裁切缺失。
- 根據 \`production-factions.ts\` 的 \`Math.max(70, enemy.radius * 4)\` 來源尺寸規範，當前 body 每格只有 96px，而需要以下真正原生 3× 的**最低每格邊長**。此處數值未額外假設更多縮放、DPR 或較大的 UI 使用處。

- 每個 telegraph 在 Canvas 中通常呈現 40×40px，至少需要 120×120px 的真正 3× 細節；目前皆只有 96×96px。
- 肉眼檢視高優先風險：\`berserker\` 的第 2／4 格（0-based）出現大幅位移／分離斬擊，\`frost-wraith\` 第 0 格有疑似不相干的底部暖色殘片；\`fire-imp\` 第 2／4 格身形縮小且邊側有分離碎片。這些屬**人工疑點**，不是確定的碰撞、判定或跨格違規，不可因此更改 gameplay。
- 新增 \`frame-qa.ts\`、\`frame-qa.test.ts\`，以實際解碼後 RGBA 判定空格、相鄰完全重複與邊緣接觸；新增 \`qa-preview.html\` 與 \`qa-preview.ts\`，以 Vite dev 開啟 \`/src/assets/es2/production/enemies/qa-preview.html\` 即可檢視所有原始影格的 1× 遊戲尺寸畫面及匯出 JSON。此頁**不是實際戰鬥畫面／自動核准工具**。
- Pixel QA 是以附件中的資產位元組進行，不能冒充在此分支執行了完整 \`pnpm test/typecheck/build/check-release\` 或實機／正式遊戲視覺驗收。
- **決策：保留 20 張原始 WebP 和原 SHA**，直到取得能證明真正原生細節、同角色連續性、完整裁切與正式 Canvas 運作的替代稿。所有狀態維持 \`needs-human-approval\`，不可把準備中的非正式候選美術標成已完成。
