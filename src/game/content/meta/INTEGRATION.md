# Meta progression integration handoff (not wired in this branch)

- This branch is **module-only**: no changes to `src/meta/profile.ts`, `src/meta/types.ts`, `SAVE_KEY`, the v2 schema, the content pack manifest, run simulation or main.
- Exported API: `createMetaState`, `applyCompletedRun`, `buyResearch`, `unlockStartingEquipment`, `unlockStartingBonus`, `getStartingLoadout`, `getAchievementStates`, `getDiscoveryEntries`, `proposeV2Migration`, `parseMetaSnapshot`, `readMetaSnapshot`, `validateMetaState` and `resetMetaState`.
- V2 migration is a **proposal**, not a write. Call `proposeV2Migration(raw)` only on a validated v2 source and never award currency during migration. Preserve the original v2 snapshot for rollback. Do **not** change or reuse the v2 `SAVE_KEY` in this feature branch. Integration owns the versioned storage envelope, transaction commit/rollback, persistence key, replay policy, UI and compatibility tests.
- Use **one** authoritative completed-run event and **one** reward writer. After replacing v2 reward handling, retire the v2 `recordRun` currency writer in that flow; never call both v2 `recordRun` and `applyCompletedRun` for the same run. Starting bonuses and research are read-only descriptions until integration applies them exactly once at the start of each run (never while a run is live).
- Every run must supply a newly issued, unguessable session/run receipt ID from the authoritative run lifecycle. V2 only stored its last 128 IDs; any earlier IDs are unknowable. Never accept an arbitrary historical replay as a newly minted receipt. The new ledger retains **all accepted IDs**, and stops accepting runs at 20,000 rather than dropping old IDs. Before reaching the ceiling, integration should design a safe rollover/retention solution, not silently evict IDs.
- Storage failures: read helpers return `null` on exceptions/invalid snapshots and do not modify storage. Integration must commit its new save atomically and handle failed `setItem` explicitly (do not acknowledge purchases or prizes as durable until persistence succeeds). This is a local save and cannot prevent manual storage tampering.
- Optional content: namespaced discovery IDs persist without their packs loaded. Integrate available pack registries for icons and detail cards while leaving absent entries locked/unknown. Do not create run-only buffs in persisted progression. Out-of-bounds and unknown state data are rejected.
- Cosmetic achievements reflect old v2 unlocked cosmetics on migration. Extra achievements and milestones inferred from historical counters are pre-claimed **without** retroactive currency. Unknown v2 per-hero history is not invented as mastery XP.
- Research is intentionally capped at 3 ranks for legacy power/vitality and 2 ranks for the new tracks, with starter-only bonuses no larger than 2% per rank; calibrate against existing run-start modifiers before integration to avoid double application or permanent power creep.
- Integration should add a profile schema v3 migration and crash-safe write/rollback tests, run receipt provenance tests, duplicate settlement across reloads, UI state transitions, and a full release verification matrix. Existing profile v2 remains completely untouched in this branch.
