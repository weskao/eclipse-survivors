# Mandatory WebP image asset policy

- **Mandatory generated-image conversion and delivery:** use [weskao/polytool](https://github.com/weskao/polytool) and its `towebp` command for all newly generated raster art (heroes, enemies, bosses, VFX, UI, backgrounds, icons, atlases, candidate frames and previews). Install with `uv tool install --from git+https://github.com/weskao/polytool.git polytool` and provide its `cwebp` dependency. Run `towebp` from an isolated staging directory (recursive by default; `-c` limits it to that directory; `-q` controls quality). Never run it indiscriminately in the repository: the current implementation removes successfully converted input files and can overwrite an existing WebP. Check that all outputs actually exist and decode correctly; a zero exit status alone is insufficient.
- **WebP-only handoff:** deliver generated images only as actual encoded `.webp` files, including manual-upload ZIP archives, candidate masters and spritesheets. Do not provide redundant PNG copies or explanation graphics embedded in sheets. Include a README and, for animation assets, a machine-readable manifest with correct WebP paths, dimensions, frame rectangles, anchors, alpha checks, original provenance and new SHA-256 hashes. Preserve original 3× detail, no upscaling, and preserve pending visual approval flags. Temporary generation PNGs are staging inputs, not delivery files. Existing platform-required PNG exceptions below remain limited to compatibility necessities, not generated art handoffs.
- **Lossless source gate:** the currently documented `towebp` implementation calls `cwebp -q`, which is lossy even at quality 100; it does not expose lossless/exact encoding. For native-3× source art, transparent sprite/atlas masters or pixel-exact migrations, require a verified Polytool version supporting lossless/exact conversion before using it; do not silently substitute lossy conversion, invent flags, or destroy source evidence. If unavailable, report the blocker and retain temporary inputs safely; a previously verified lossless WebP may be reused and delivered without re-encoding. Never claim Polytool was executed if it was not. Do not downgrade any QA or provenance gate.
- **WebP-first for all project raster art:** use local `.webp` for game/UI images, portraits, sprites, atlases, textures, backgrounds, decorations and screenshots. Convert required PNG-only display assets to WebP and update all imports, CSS/HTML, manifests, tests, scripts, cache/pack references and docs before removing their PNG copies. Do not keep redundant PNG exports of a WebP display asset.
- **Hero cleanup (mandatory):** Do not commit PNG and WebP copies merely for the same display role. Prefer lossless WebP for retained hero masters, with decoded RGBA, dimensions, alpha and provenance verified against the original; update source path/hash manifests and tests atomically before deleting PNGs. An exact duplicate blob can be removed immediately after redirecting metadata to its canonical copy. Rejected, unused direction drafts may be retired from the working tree when their original commit/path/blob/hash and rejection reason are recorded and no active consumer needs them. Keep independent approved or pending sources needed for handedness review and original-source QA until verified replacements exist. Never weaken the art acceptance gate to reduce file count.
- **Verify before deletion:** preserve dimensions, alpha, native 3× detail and color management; prefer lossless WebP with exact decoded RGBA verification for sprites, icons, UI and source conversions. Never replace a different existing WebP with a similar PNG. Check all tracked references (including dynamically resolved names), source provenance, animation, metadata, build and platform behavior. If a safe migration cannot be demonstrated, retain the PNG and document why. Never rename extensions without encoding, and never delete a sole source on filename similarity.
- **Compatibility/provenance exceptions:** keep platform-required or compatibility-sensitive PWA/iOS home-screen icons and social preview images in PNG when changing format is unsafe or unverified. Preserve original character masters, repair inputs, source hashes, QA/CI evidence and other irreplaceable source or metadata until a verified equivalent migration updates all consumers and provenance. Temporary PNGs from image/capture tools must not become committed display assets. No destructive blanket deletion.
- **Keep source-only evidence out of release bundles:** immutable provenance masters may stay in Git, but exclude their redundant display copies from `dist/` once every runtime consumer uses the verified WebP. Keep required platform icons and unrelated static assets intact. The release check must enforce this distinction.
- **After migration:** record converted/deleted paths, exceptions and exact byte/pixel validation; re-run relevant tests, `pnpm build` and `pnpm check-release`. Keep quality and visual QA gates intact.
