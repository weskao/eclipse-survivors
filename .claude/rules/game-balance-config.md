# Mandatory centralized gameplay balance configuration

Applies to every Create / Read / Update / Delete of gameplay numbers, character attributes, XP, leveling, skills, weapons, effects, enemies, bosses, pickups, treasure, events, difficulty modes and future systems.

## Single source of truth

1. **Data first:** Store designer-tunable numbers by domain in `src/game/balance/<domain>.json` (currently `world`, `heroes`, `progression`, `skills`, `weapons`, `events`, `enemies`, `combat`, `evolutions`, `modes`, `bosses`, `relics`, `meta`). `src/game/balance/index.ts` imports each JSON and composes `tuning`; `src/game/config.ts` remains the sole typed public `BALANCE` access point. Do not duplicate numbers in a Vue component, combat loop, test, translation or hidden constant.
**Permanent progression:** `meta.research` owns rank caps, per-rank benefits and escalating research prices; `meta.runRewards` owns repeatable currency and mastery earnings. `meta.achievementEmbers`, `meta.milestoneEmbers`, `meta.startingEquipment` and `meta.startingBonuses` own other permanent-shop values. `researchCost()` is the only price function, used by both v2 compatibility and v3 transactions. Preserve existing saves and prices of owned ranks, apply next-run bonuses only once and never pay a run or milestone twice. Do not introduce arbitrary lower caps than the existing safe-integer wallet.
2. **Decide reuse vs. new JSON before editing:** Identify the feature's owner and check whether an existing JSON already contains a matching type of gameplay parameter. **Same responsibility or reusable formula → extend the existing domain JSON and reuse shared defaults.** **Different feature lifecycle/responsibility with a distinct set of values → create a new descriptively named domain JSON.** Cross-system shared coefficients belong to one owning domain; consumers read them through `BALANCE`, not copies. Keep per-hero, per-boss, per-weapon and per-skill overrides within their owning domain. Do not create one JSON per object or field merely for convenience.
3. **Typed consumers and registration:** When adding a new domain JSON, import/register it under the matching key in `src/game/balance/index.ts`, extend `satisfies` validation in `src/game/config.ts` as applicable, and update `src/game/balance.test.ts`. Access values only through `BALANCE` in runtime code. Validate union-key completeness (e.g. `JobId`, `UpgradeId`, `MobType`, `WorldEventKind`, `WeaponKey`), numeric ranges, and required keys. Do not mutate imported values or JSON.parse in the hot path.
4. **Separate data from behavior:** Keep `Math.round`, cooldown, target selection, collision and sampling algorithms in their existing small modules, but move tunable multipliers, absolute values, probabilities, caps, durations, radii and thresholds to the JSON. Preserve deterministic seeded RNG, max-target/projectile limits and player fairness. Physics epsilon values, generated coordinates, frame geometry, artwork colors, UI spacing and mathematical constants such as `Math.PI` are **not** gameplay-balance knobs; do not move them blindly.
5. **Real code and UI must agree:** Hero selection reads the same `JOB`/`HERO_DEFINITIONS` data as combat. XP bars follow `BALANCE.progression`; ability cards and translations must reflect actual configured effects. Keep English and zh-TW in `src/i18n.ts`; when numbers appear in text use parameterized `t()` templates when possible, not stale literal percentages.
6. **Balance invariants:** Nonnegative finite HP, attack, speeds, durations and costs; probabilities in `[0,1]`; event weights sum to 1; sensible growth curve; level caps reached and removed from offers; no unbounded high-rank AoE, stacking, FX or projectiles. Explicitly preserve special constraints on boss/elite encounters and mid/late-game challenge.
7. **TDD and verification:** Add a RED failing test for every new numeric domain or balance rule before changing the JSON and consumers. Verify `src/game/balance.test.ts`, hero HP/runtime/menu, progression curves, event weights, skill radius/damage, weapons, and seeded simulations. Run `pnpm test`, `pnpm typecheck`, `pnpm build`, `pnpm check-release`; capture real desktop and mobile portrait/landscape screenshots for UI changes. Document the changed values and the baseline vs updated difficulty. Never claim CI green while it fails for unrelated reasons.
8. **Incremental migration:** When touching legacy gameplay values, move tunable literals into the appropriate existing `<domain>.json`; create a new JSON only after applying rule 2. Avoid unrelated rewriting or extracting coordinate/shader constants. Maintain the public `BALANCE` field structure across file moves. Test that each domain JSON exactly matches `BALANCE[domain]`, and do not ship a second monolithic balance file.

## Boss locomotion and attack fairness

- Every newly introduced or updated ES2 boss must declare its pursuit speed, standoff distance and optional orbit speed in `src/game/balance/bosses.json` under `movement`, with shared phase escalation from `phaseMovementMultipliers`. Do not hard-code gameplay speeds in renderers or duplicate them in boss-specific classes.
- Pursuit must use current world-space hero/boss positions and respect slow/stagger, pause, boss defeat and the existing step obstacle resolver. Keep telegraphed attack geometry fixed during windup, so visibly escaping an indicated area remains reliable; no invisible mid-windup redirects or unavoidable instant lunges.
- Preserve per-boss visual identity and reduced-motion preference. Reuse the existing approved runtime phase atlas for lightweight movement until separately sourced, genuine native-3x locomotion frames are reviewed. New animation assets require source, per-frame QA, actual-game screenshots and human review; a QA-PENDING candidate must not silently ship in production.

## Typical change sequence

- Open `src/game/balance/index.ts`, the relevant `src/game/balance/<domain>.json` and `src/game/config.ts`; identify its owner and reused scaling parameter before choosing a new domain.
- Update focused tests first; edit the existing domain JSON, or create and register a new domain JSON only if truly different; wire consumers through the existing `BALANCE` import.
- Update matching bilingual descriptions, home/selection UI, and any charts or docs derived from live config.
- Check all six hero archetypes, level 1–20 and late levels, all three rarities, caps, boss behavior, treasure distribution and 130-mob performance.
