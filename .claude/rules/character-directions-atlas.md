# Character directions, animation and atlases — character-art-3x §3 and §4

Continues the always-loaded `character-art-3x.md`; section numbers are kept so existing §3/§4 references resolve here.

## 3. Direction and animation contract

- **Direction index/order:** `0=E, 1=SE, 2=S, 3=SW, 4=W, 5=NW, 6=N, 7=NE`. If art source column order differs, use an explicit tested mapping.
- Provide an accurately faced `idle/ready` view for all eight directions, using distinct sources where required and explicitly verified horizontal reuse where visually equivalent. Where animated, author **consecutive real poses** for run/dash, basic attack/cast, special skill and appropriate hurt/death/victory. Target at least 10 run frames and 12 basic attack/cast frames where the game's `HeroAnimation.count` requests them; use a documented frame-timing map when art has fewer frames.
- Motion must have actual anatomy changes (stride, weight shift, cloak/cloth, blade/staff trajectory, shield and effect timing), stable identity and foot placement, and correct anticipation → strike/projectile release → recovery. Do not fake an eight-direction action by copying/mirroring a single right-facing sequence, or by toggling idle/guard frames and calling it running. A sideways eight-frame run strip is **not** an eight-direction run; never relabel a single pose, mirror a wrong-handed/shield-bearing pose or cycle across unrelated frames. Keep equipment hand, ground contact, frame crop and visual scale stable.
- **Five-source-first policy for eight-direction animation (mandatory):** For each character and pose, first inventory the five canonical authored facings `E, SE, S, N, NE`. Plan `W ← E`, `SW ← SE`, `NW ← NE` as draw-time horizontal reflections, not extra image files. Author only missing canonical facings and independently justified exceptions. Do not generate all eight by default; evaluate existing source art, handedness, text/emblems, lighting and effect trajectories first. For symmetric equipment, validate all eight actual runtime facings, then reuse the same decoded texture, exact cell and anchor via `scale(-1, 1)` or equivalent. For asymmetric equipment, preserve independent correct facings until a visual comparison demonstrates the reflection is equivalent (or a separate rigid weapon layer preserves handedness). The five-source plan is not a universal five-image limit: each action still needs its own consecutive poses and frame count. Keep a per-character/per-pose source/target allowlist and regression tests. Never generate duplicate mirrored exports; retire an independent file only after verifying the replacement at real game scale, all references, and the full QA gate. Existing independent SW/NW hero candidates remain in service until that evidence exists.
- **Asymmetric facing exception — mandatory before ordering art:** A flattened full-character sprite containing a one-handed staff, sword/shield, asymmetric costume or directional attack/VFX must not be reflected if the transform swaps the canonical equipment hand, emblem or mechanically significant effect. If that asymmetry cannot be corrected by an existing independently rendered rigid equipment layer, author the opposite facing independently; five is a planning baseline, not a cap. For the present ES2 run/dash candidates, Shadowblade E→W is already allowed for DEV QA and existing independent SW/NW are retained; Spirit Summoner requires independently correct W and NW (existing NW batch 6 remains review-only until handedness is demonstrated); Crimson Paladin requires independently correct W, NW and NE (reuse the batch-7 NE candidate if supplied and acceptable). Both staff and sword/shield heroes retain their existing SW rather than reflecting SE. Reuse verified assets instead of regenerating them. Review all facings against the canonical portrait and at actual game size; never mark candidates approved merely to satisfy direction counts. Apply the same decision separately for attack/cast, special and other poses, which have distinct timing and equipment requirements.
- **Horizontal reuse, mandatory assessment before image generation:** Inventory existing source images, runtime atlases, manifests, unintegrated candidates and current consumers before commissioning or regenerating any directional artwork. Inspect the canonical identity, costume, weapons/handedness, lettering/emblems, lighting and effect trajectories. Record the reuse decision per character/pose/direction and generate a new source only if no compatible existing source or safe reflection can satisfy the requirement. An explicit per-character/per-pose horizontal reflection may reuse E↔W, SE↔SW or NE↔NW only when the same motion remains visually and mechanically correct. Reflect at draw time around the actor anchor (Canvas save/scale/restore or equivalent GPU transform), share the same decoded source and crop, preserve foot alignment and gameplay geometry. Never store duplicate mirrored PNG/WebP files merely for facing. Prefer an existing independent correct source over a mirror. N/S are not reflections of each other. Single-hand staff, sword/shield, asymmetric equipment or direction-dependent effects require independent art unless visual review demonstrates equivalence without reversing important details. Track authored vs reflected directions separately, record source/target mapping and QA, and never count reflected frames as independently authored or as new native-detail pixels. Shadowblade E→W run/dash is allowed for opt-in candidate QA; attack/special and the other two heroes are not automatically allowlisted. No release promotion without actual visual approval. 
- A facing with only idle/guard is **incomplete**. Preserve a same-character fallback for that facing, mark `QA_PENDING`, and do not claim full eight-direction run/combat continuity.
- Keep weapon dimensions, left/right hand assignment, origin and real collision mechanics independent from visual frame silhouettes. No animation may move hitboxes, create duplicate projectiles or replace combat timing.

## 4. Splitting atlases and deterministic layout

- Follow the mandatory [WebP image asset policy](webp-assets.md): WebP is the sole hero display/runtime raster format; prefer lossless WebP for source masters too. Audit rejected/duplicate direction images and remove them from HEAD after recording exact provenance and confirming no live consumer or acceptance test depends on them. Do not commit a duplicate PNG export of a verified WebP. Convert PNG-only display art without resampling or losing alpha; retain original master/repair/QA PNGs with essential provenance until a safe equivalent migration of hashes, metadata, manifests and tests is proven. When uncertain, retain rather than delete.

- Use **multiple atlases when needed** instead of shrinking character art to fit. Example project paths (actual names depend on content): `src/assets/es2/production/heroes/<character-id>/<pose>-<direction>@3x.webp` or `<character-id>-<pose>-<sheet-index>@3x.webp`.
- Document for **every** atlas: file path, canonical character ID, source art reference, native source cell size, runtime cell size, `3×` source scale, columns/rows, direction order, pose/frame ordering, independent frame count and timing, foot anchor, transparency, SHA-256, compressed bytes, budget, and human QA status.
- Pack fixed-size frames with enough transparent gutters (or extrude transparent edge pixels) to avoid cross-cell bleed under filtering. Source coordinates must be exact integers and within the image; no fractional cell crop and no borrowing adjacent character parts.
- **ES2 split-atlas safety:** Existing 448×448 source cells reserve 8px transparent gutters on each side. Canvas consumers MUST sample only the 432×432 interior (`x+8, y+8`) and compensate destination dimensions/offsets so the visual scale and measured foot anchor remain unchanged. When an atlas is rebuilt with a different cell/gutter geometry, update its manifest, renderer, anchors and tests atomically. Never silently erase a limb/weapon that extends into a cell edge; regenerate the isolated source frame instead, with transparent padding and visual QA.
- Keep each atlas within practical device maximum texture dimensions (prefer `≤4096×4096`, subject to real device testing). Optimize compressed bytes **and decoded memory**. Lazy-load the current character's required atlas at event/pose boundaries, never in the Canvas frame loop. Cache decoded images and pre-rendered frames with a strict bound; evict on character/art changes.
- Respect `prefers-reduced-motion`: use the same character's still, fully rendered frame, never blank screen or a different job's rig.

## Existing ES2 transition

The three new heroes currently have `900×900` portrait WebPs and `3072×1920` nominal `384×384`-cell 8×5 motion sheets with authentic source drawings about `198×198` per cell. These **are not yet native 3× character-movement masters**. They have eight-direction idle/guard but only side-facing authored running/attack/special frame sequences. Retain `QA_PENDING` until real higher-detail, complete directional sources are generated, committed and wired; do not falsely claim that more frames were produced just because interpolated output dimensions are large.
